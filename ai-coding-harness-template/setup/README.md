# 환경 세팅 레이어 (Environment Setup)

> `templates/` 가 **AI 에게 무엇을 지시할지**(문서 하네스)를 담는다면,
> `setup/` 은 **AI 를 어떤 환경에서 돌릴지**(설정·권한·MCP·메모리)를 담습니다.

문서 하네스만 새 PC 로 옮기면, 에이전트는 규칙은 알지만 도구·권한·메모리가 없는 상태로 시작합니다.
이 폴더는 그 나머지 절반 — **Claude Code 환경 재현 절차**를 다룹니다.
하네스 개념·문서 구조·이식 방법론은 [README.md](../README.md) 와 [GUIDE.md](../GUIDE.md) 를 참고하세요.

**처음이라면** 최상위 [SETUP.md](../SETUP.md) 가 상황별(새 PC / 기존 프로젝트 / 처음부터) 진입점입니다.
채워진 실물 사례는 [profiles/](../profiles/) 에 있습니다.

---

## 구성

```
setup/
├── README.md      # ← 이 문서 (역할 분리 + 이식 범위)
├── checklist.md   # 새 PC / 새 프로젝트 세팅 순서 (0~8단계 체크박스)
├── settings/      # settings.json 3계층(전역·프로젝트·로컬) 스켈레톤 + 권한 운영 규칙
├── mcp/           # MCP 서버 등록 절차·스코프·파일 위치 (사용 정책은 docs/TOOLS.md)
├── memory/        # 영속 메모리 디렉터리 구조·노트 유형·frontmatter 규약
└── hooks/         # hook 이벤트·설정 구조·도입 판단 기준 (선택 레이어)
```

세팅을 처음 하는 경우 [`checklist.md`](checklist.md) 부터 순서대로 따라가세요.
각 하위 폴더 문서는 그 단계의 상세 근거입니다.

## 무엇을 옮기고 무엇을 새로 만드나

환경 레이어는 **통째로 복사하면 안 됩니다.** 대부분의 실제 설정 파일에는
그 머신에서만 유효한 절대경로·세션 임시경로·계정 정보가 섞여 있기 때문입니다.

| 항목 | 새 환경에서 | 이유 |
|------|------------|------|
| 전역 스칼라 키 (`model`·`effortLevel`·`autoUpdatesChannel`) | **그대로 복사** | 머신과 무관. 몇 줄이면 끝나고 효과가 큼 |
| `permissions.allow` — 재사용 패턴 | **골라서 복사** | `Bash(<명령>:*)` / `Read(//<경로>/**)` / `WebFetch(domain:<호스트>)` 형태만 |
| `permissions.allow` — 일회성 정확 명령 | **버림** | 실사용 중 자동 누적된 찌꺼기. 새 환경에서 다시 쌓임 |
| `permissions.deny` | **새로 작성** | 위험 명령 차단은 산문 규칙이 아니라 여기서 강제 |
| `permissions.additionalDirectories` | **새로 작성** | 새 머신에 실제로 존재하는 경로만 |
| MCP 서버 **구조**(이름·transport·명령 형태) | 구조만 복사 | 접속정보·토큰은 `${환경변수}` 로 치환. 평문 복사 금지 |
| 메모리 **운영 규칙**(유형·frontmatter·인덱스 관례) | **그대로 복사** | 프로젝트 무관한 규약 |
| 메모리 **노트 내용** | 새로 쌓음 | 메모리는 프로젝트별로 격리됨. 남의 프로젝트 지식을 끌고 오지 않음 |
| 플러그인 선언 2키 (`enabledPlugins`·`extraKnownMarketplaces`) | **그대로 복사** | 사람이 쓰는 값은 이 둘뿐 |
| 플러그인 설치 기록 파일 | **복사 금지** | 기계 생성. 설치 시 자동 재작성됨 |
| `~/.claude.json` 통째 | **복사 금지** | 설정 파일이 아니라 계정·상태 저장소 |
| 자격증명 파일 · 세션/히스토리 산출물 | **복사 금지** | 비밀정보 + 런타임 부산물 |

> 판정 기준 한 줄: **"다른 머신에서도 참인가?"** — 참이면 복사, 거짓이면 새로 작성.

## 자격증명 취급

> 환경 레이어(설정·권한·MCP·hook) 전반에 적용되는 **정본**입니다.
> 하위 문서는 각자 고유한 사실 한 줄만 두고 여기로 링크합니다.

- **git 추적 파일에 접속문자열·토큰·비밀번호를 절대 넣지 않습니다** — `.mcp.json`, `<리포>/.claude/settings.json`,
  hook 스크립트 모두 해당. 값이 필요하면 ① 개인 파일(`~/.claude.json`, `.claude/settings.local.json`)
  또는 ② 환경변수 참조(`${VAR}`) 둘 중 하나로 넣습니다.
- **권한 규칙 문자열에 접속정보를 넣지 않습니다.** 명령 전체를 allow 에 박다 보면 DB 계정·비밀번호가
  설정 파일에 평문으로 남습니다. 자주 쓰는 명령은 인자를 뺀 **접두 패턴**으로 승격시키세요.
- **문서·이슈·커밋 메시지에 적을 땐** `<db-host>` · `<user>` · `<password>` 형태 플레이스홀더로 마스킹합니다.
- 이미 평문이 들어간 파일은 값을 치환하는 것으로 끝내지 말고, **그 자격증명 자체를 교체**하세요.
  커밋 이력·백업·동기화 사본에 이미 퍼졌다고 가정합니다.
- 보안 규칙 전반의 정본은 [`docs/SECURITY.md`](../templates/docs/SECURITY.md) 입니다.

## 문서 하네스와의 경계

두 레이어가 겹쳐 보이는 지점이 있어 담당을 고정해 둡니다. 같은 사실을 두 곳에 적지 않습니다.

| 주제 | 담당 |
|------|------|
| MCP **등록 방법**·스코프·설정 파일 위치 | `setup/mcp/` |
| MCP **사용 정책**(읽기 전용 / 쓰기 금지 / 브라우저 규칙) | [`docs/TOOLS.md`](../templates/docs/TOOLS.md) |
| 자동 검증을 hook 으로 **강제하는 방법** | `setup/hooks/` |
| 어떤 검증을 도입했고 무엇을 보류했는지 | [`docs/FEEDBACK_LOOPS.md`](../templates/docs/FEEDBACK_LOOPS.md) |
| 무엇을 커밋하고 무엇을 제외하는지 | [`docs/GIT_WORKFLOW.md`](../templates/docs/GIT_WORKFLOW.md) |
